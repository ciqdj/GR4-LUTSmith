GR4-LUTSmithは、カラーグレーディング用のLUT（`.cube`）から、そのルックを**イメージコントロール**のルックとして搭載したGR IVのファームウェアを作ります。静止画、動画モード、ファインダー表示で撮影に使えるほか、**RAW Development**でも使えます。カメラのそれ以外の部分はすべてそのままで、いつでも公式ファームウェアに戻せます。

このリポジトリにRICOHのファームウェアは含まれていません。公式ファームウェアはご自身でRICOHからダウンロードしてください。同梱のツールが、お使いのコンピューター上で、それをあなたのルック入りのバージョンに作り変えます。

> **非公式です。ご自身の責任でお使いください。** RICOH IMAGINGが作成・承認したものではありません。改変したファームウェアをインストールすると、保証が受けられなくなる場合があります。先に[はじめる前に](#はじめる前に)と[リスク](#リスク)をお読みください。

## 仕組み

GR IVはLUTを直接扱えません。カメラのルックは、いくつかのネイティブな調整機能で作られています。カラーミックス、トーンカーブ、コントラスト設定、そして**色相別補正**（色相を12の範囲に分け、範囲ごとに別々に色を変える機能）です。GR4-LUTSmithはLUTをこれらの調整機能に**フィット**させ、カメラでどこまで近づけるかを測定してから、はじめてファームウェアを書き出します。

- **トーンや全体の色を変えるルック**は、とてもよくフィットします。フィルム風のカーブ、コントラスト、フェードした黒、暖色や寒色の色かぶり、全体的な彩度の変化などです。
- **個々の色相を別々に動かすルック**（ティール＆オレンジ、緑や空の色を変えるフィルムシミュレーションなど）は、**色相別補正**でフィットします。カラーミックスだけの場合よりずっと近づきます。色の鮮やかさに強く左右される変化（たとえば最も鮮やかな赤だけ）は近似にとどまり、その場合はツールが知らせます。
- **Logやカメラ固有の変換用LUT**（S-Log、V-Logなど）には対応していません。通常の（Rec.709 / sRGB）写真用に作られた「クリエイティブ」LUTを使ってください。

フィットは、2つの色の見た目の違いを表す標準的な尺度、**CIEDE2000**で評価します。目安として、**1未満は並べて比べても見分けにくく**、2前後はわずかに見える差です。

| 結果 | 意味 |
| --- | --- |
| **良好**（good） | 平均差が1未満、かつ95 %の色が2未満：同じに見える |
| **近似**（approximate） | 平均が2未満：近いが、一部の色に見える差がある |
| **不十分**（poor） | カメラではLUTの色域全体を再現できない。**日常的な色**が合っていれば、ファームウェアは書き出される（[評価が不十分なLUTの場合](#評価が不十分なlutの場合)を参照） |

どのLUTも3つの方法で測定します。色域全体、**ColorChecker**チャートの日常的な24色（肌、空、草木など）、そして**ニュートラルグレー**（色かぶりが最も目立つところ）です。ご自身の写真を指定すると（`--photo`）、その写真でも測定します。

## 得られるもの

インストール後、イメージコントロールの一覧の最後は次のようになります。イメージコントロール、スタンダード、彩度、色相以外のメニュー名は、カメラを英語に設定したときの表示で記載しています。

| 表示名 | ルック | 静止画 | 動画 |
| --- | --- | :---: | :---: |
| HDR Tone | （今あるカラーのルック） | ✓ | |
| スタンダード | スタンダード（モノクロ） | ✓ | ✓ |
| Solid | Solid（モノクロ） | ✓ | ✓ |
| Soft | Soft（モノクロ） | ✓ | |
| **High Contrast** | **あなたのLUTのルック（カラー）** | ✓ | ✓ |
| Grainy | Grainy（モノクロ） | ✓ | |
| HDR Tone | HDR（モノクロ）*（実験的）* | ✓ | |

- ルックには**High Contrast**（最初の「HDR Tone」から数えて4つ後の項目）の名前とアイコンが使われます。代わりに**Cinema (Yellow)**、**Vivid**などのスロットを選ぶことも、複数のスロットを使うこともできます。[スロットの選び方](#スロットの選び方)を参照してください。[独自の名前](#スロットの名前)や[独自アイコン](#独自アイコン)を表示することもできます。
- ルックは、**すべてのスライダーが0**、シャープネスが標準値、**粒状感オフ**の状態で始まります。LUTのルックはこの設定を前提に組み込まれています。スライダーはそこから通常どおり働き、あなたのルックが出発点になります。
- GR IV Monochromeの5つのモノクロルックも、GR4-MonoUnlockと同様に使えます。
- 既存のルックはすべてそのままです。

## はじめる前に

- **カメラ：** RICOH GR IV（標準のカラーモデル）。ほかの機種には対応していません。
- **カメラのファームウェアがすでに1.11である必要があります。** バージョンはカメラのセットアップメニューで確認してください。
  - 古いバージョンの場合：まずRICOHの公式ファイルを使い、通常の方法で1.11にアップデートしてください。
  - 新しいバージョンの場合：**このツールは使わないでください。** 対応しているのは1.11だけです。
- **公式ファームウェアファイル。** RICOH IMAGINGの公式GR IVサポートページから、**ファームウェアバージョン1.11**をダウンロードします。必要に応じて展開し、**`fwdc248b.bin`** というファイルを取り出します。
- **満充電のバッテリー。** ファームウェアアップデート中に電源が切れることは絶対に避けてください。
- フォーマットしてもよい**SDカード**。
- `.cube`ファイル（3Dまたは1D）の**LUT**と、それが**sRGB**用（ほとんどのLUT）か**Adobe RGB**用かの情報。
- **推奨：** GR IVで撮影したDNG写真。ツールはこれを使って、実際の写真でルックを確認し、プレビューを作ります。
- 設定し直したくないカスタム設定（C1、C2など）は控えておいてください。

その後、[アプリ](#アプリ)または[コマンドライン](#コマンドライン)でファームウェアを作ります。

## アプリ

### ダウンロード

[最新のリリース](../../releases/latest)から、お使いのコンピューター用のファイルをダウンロードします。

| コンピューター | ファイル |
| --- | --- |
| Appleシリコン搭載のMac（M1以降） | `GR4-LUTSmith-<version>-macOS-AppleSilicon.zip` |
| Intelプロセッサ搭載のMac | `GR4-LUTSmith-<version>-macOS-Intel.zip` |
| Windows 10または11（64ビット） | `GR4-LUTSmith-<version>-Windows-x64.zip` |

macOS 12（Monterey）以降が必要です。どのMacかわからない場合は、Appleメニュー → **このMacについて**を開きます。「チップ Apple M…」と表示されればAppleシリコン、「プロセッサ Intel」と表示されればIntelです。

各zipには、アプリと`Licences`フォルダ（アプリを構成する部品のライセンス）が入っています。

### 初めて開くとき

このアプリは無料で、有料のAppleやMicrosoftの証明書で署名されていません。そのため、信頼してよいかを、コンピューターが一度だけ確認してきます。

**macOS**

1. ファイルを解凍し、**GR4-LUTSmith**をアプリケーションフォルダに移動します。
2. アプリを開きます。macOSに、悪質なソフトウェアがないか確認できないと表示されたら、**完了**（macOS 15）または**キャンセル**を選びます。
3. **システム設定 → プライバシーとセキュリティ**を開き、下にスクロールしてGR4-LUTSmithに関するメッセージを探し、**このまま開く**を選んでから、パスワードで確定します。macOS 12〜14では、代わりにControlキーを押しながらアプリをクリックし、**開く**を選んで、もう一度**開く**を選ぶこともできます。

以降は普通に開きます。

**Windows**

1. zipを右クリック → **すべて展開…** を選び、展開された**GR4-LUTSmith**フォルダを開きます（zipの中から実行しないでください）。
2. **GR4-LUTSmith.exe**を開きます。「WindowsによってPCが保護されました」と表示されたら、**詳細情報 → 実行**を選びます。

フォルダ全体をまとめておいてください。アプリと同じ場所に`_internal`フォルダが必要です。

### 使い方

アプリは画面上で手順を案内します。カメラのファームウェアファイル、LUT（必要に応じてDNGも）、スロットとその名前とアイコン、フィット、ビルドの順です。`fwdc248b.bin`は指定した場所に保存されます。その後、[カメラに入れます](#カメラに入れる)。

- **言語：** アプリはコンピューターの言語に従います。ウィンドウ上部で変更できます。これは、スロット名を確認するときの基準になるカメラの言語でもあります（[スロットの名前](#スロットの名前)を参照）。
- **外観：** ウィンドウ上部で、システム、昼、夜から選べます。
- 左側の**ファームウェアファイルを確認**では、`fwdc248b.bin`がRICOHの公式ファイルか、GR4-LUTSmithで作られたもの（どのルック入りか）か、それ以外かがわかります。
- 共有されたルック（`.json`）もアプリで使えます。最初のページで「共有ルック」を選びます。
- **複数の試行を同時に：** 「フィット」ページで、試行回数と同時実行数を選びます（試行ごとにプロセッサのコアを1つ使います。[試行を増やす](#試行を増やす)を参照）。各試行の進み具合が表示されます。実行中に試行を追加でき、「すべて停止」を押しても完了した試行は残ります。結果は、試行が終わるたびに表に加わります。

### うまくいかないとき

- **macOSでアプリが壊れていると表示される**：もう一度ダウンロードし（ファイルが途中で切れています）、[このプロジェクトから来たものか確認する](#ダウンロード)の方法で確認してください。
- **Windowsでアプリが起動しない**：zip全体を展開したかを確認し、展開したフォルダから`GR4-LUTSmith.exe`を実行してください。
- **ファームウェアファイルが受け付けられない**：アプリが受け付けるのは、RICOHの改変されていないGR IV 1.11の`fwdc248b.bin`だけです。GR4-LUTSmithですでに変更したファイルは、さらに変更できません。改変されていないファイルから始めてください。

## コマンドライン

### 1. 準備

**[uv](https://docs.astral.sh/uv/)** をインストールし（Pythonと、ツールに必要なものをすべてインストールします）、このフォルダでターミナルを開いて、次を実行します。

```sh
uv sync --extra photo
```

<details>
<summary>uvを使わない場合</summary>

<br>

Python 3.9以降で：

```sh
python3 -m pip install numpy rawpy pillow
python3 gr4_lutsmith.py make my_look.cube ~/Downloads/fwdc248b.bin --photo R0001234.DNG
```

`rawpy`と`pillow`が必要なのは、`--photo`と`preview`を使うときだけです。

</details>

### 2. ファームウェアを作る

パスはご自身のものに置き換えてください。

```sh
uv run gr4_lutsmith.py make my_look.cube ~/Downloads/fwdc248b.bin --photo R0001234.DNG
```

| オプション | 内容 |
| --- | --- |
| `--space adobe` | LUTがAdobe RGB用に作られている |
| `--photo R0001234.DNG` | 写真でもルックを確認する（任意ですが推奨） |
| `--slot vivid`、`--slot cinema-yellow`、… | High Contrastではなく、別のルックの代わりにあなたのルックを入れる：[スロットの選び方](#スロットの選び方) |
| `--name "My Look"` | スロットを独自の名前で表示する：[スロットの名前](#スロットの名前) |
| `--icon my_icon.png` | スロットに独自のメニューアイコンを付ける：[独自アイコン](#独自アイコン) |
| `--turns 3` | フィットを3回実行し、良いものを残す：[試行を増やす](#試行を増やす) |
| `--jobs 3` | それらの試行を最大3つ同時に実行する：[試行を増やす](#試行を増やす) |
| `--after-curves` | 2つ目のカラーミックスも試す：[カーブ後の色補正](#カーブ後の色補正) |

ツールは次のことを行います。

1. 渡されたファイルが本物の公式1.11ファイルであることを確認します。
2. LUTをフィットし（数分かかり、色相別補正にさらに1〜2分かかります）、どれだけフィットしたかを表示します。
3. ファームウェアをビルドし、確認します。

うまくいくと、最後は次のようになります。

```
  result: GOOD  (ΔE00 0.6, p95 1.42; without the look 2.09)
  on your photo: ΔE00 1.22 (without the look 2.55)
  ...
wrote output/my_look/fwdc248b.bin  (SHA-256 …)
Copy this file to the root of the SD card and run the camera's firmware update.
Then choose High Contrast in Image Control: your look is there.
```

ツールは最初に、ルックがどのスロットに入るかも表示します。たとえば`slot: High Contrast (replaces the hidden monochrome High Contrast look)`のように表示されます。

出力フォルダ`output/my_look/`には`look.json`（フィットしたルック）も入り、プレビュー（ステップ3）も置けます。`look.json`はほかのGR IVユーザーと共有できます。受け取った人は、もう一度フィットしなくても同じルックをビルドできます（[共有されたルックを使う](#共有されたルックを使う)を参照）。

LUTをうまく再現できない場合や、ファームウェアファイルが公式の1.11でない場合、ツールは`refused: …`と表示し、**ファームウェアを書き出しません**。

### 3. プレビュー（任意）

```sh
uv run gr4_lutsmith.py preview output/my_look/look.json R0001234.DNG
```

これにより、3つのパネルからなる`output/my_look/preview.jpg`が書き出されます。ルックなしのカメラ、LUTそのもの、そしてルック**あり**のカメラです。LUTのパネルには`.cube`ファイルが必要です。ツールは`look.json`と同じ場所か現在のフォルダでファイルを探します。`--lut my_look.cube`で指定することもできます。ファイルがない場合、プレビューにはほかの2つのパネルが表示されます。比べるのは色とトーンです。シャープネスとノイズはシミュレートされません。

その後、[カメラに入れます](#カメラに入れる)。

## カメラに入れる

アプリで作ったファームウェアでも、コマンドラインで作ったファームウェアでも、手順は同じです。

### 1. SDカードにコピーする

1. **カメラでSDカードをフォーマットします。**
2. **`fwdc248b.bin`**（コマンドラインの場合は`output/my_look/fwdc248b.bin`）をカードの**最上位**にコピーします。フォルダの中には入れず、名前は`fwdc248b.bin`のまま変えないでください。

### 2. カメラをアップデートする

1. 満充電のバッテリーとSDカードを入れます。
2. RICOHの公式GR IVファームウェアアップデート手順に従い、カメラのセットアップメニューからファームウェアアップデートを開始します。
3. **カメラには、バージョン1.11からバージョン1.11へのアップデートと表示されます。** これは想定どおりです。改変したファームウェアはバージョン番号をそのまま保ちます。アップデートを確定してください。

> [!CAUTION]
> アップデートが完了してカメラが再起動するまで、**カメラの電源を切ったり、バッテリーカバーやカードカバーを開けたり、カードを取り出したりしないでください。**

### 3. 撮影する

- **イメージコントロール**を開き、**High Contrast**（最初の「HDR Tone」の後）を選びます。カラーになっています。別のスロットを選んだ場合は、その項目を選んでください。
- ファームウェアのバージョンは**1.11**のままです。これは正常です。
- 誤ってアップデートが再び始まらないように、カードから`fwdc248b.bin`を削除してください（またはカードをフォーマットします）。

あとで別のLUTに変えるときは、**公式**ファイルから新しいファームウェアを作り、同じ方法でインストールします。

### 公式ファームウェアに戻す

代わりにRICOHの**公式** `fwdc248b.bin` を使って、手順1〜2を繰り返します。カメラにはまた**1.11 → 1.11**と表示されます。確定すれば、カメラは元の状態に戻ります。

## 自分好みにする

ルックをどこに入れるか、どんな名前にするか、メニューでどう見せるか。アプリではスロットのステップで、コマンドラインでは`make`と`build`のオプションで設定します。

### スロットの選び方

あなたのルックは、カメラのルックの1つと置き換わります。どれと置き換えるかは`--slot`（`make`と`build`）で選びます。`uv run gr4_lutsmith.py slots`を実行すると、同じ一覧がターミナルに表示されます。

| `--slot` | 表示名 | 置き換え対象 | 静止画 | 動画 | 追加スライダー |
| --- | --- | --- | :---: | :---: | --- |
| `high-contrast`（既定） | High Contrast | 非表示のモノクロルック「High Contrast」 | ✓ | ✓ | — |
| `cinema-yellow` | Cinema (Yellow) | RICOHの「Cinema (Yellow)」ルック | ✓ | ✓ | 彩度、色相 |
| `cinema-green` | Cinema (Green) | RICOHの「Cinema (Green)」ルック | ✓ | ✓ | 彩度、色相 |
| `vivid` | Vivid | RICOHの「Vivid」ルック | ✓ | ✓ | 彩度、色相 |
| `positive-film` | Positive Film | RICOHの「Positive Film」ルック | ✓ | ✓ | 彩度、色相 |
| `negative-film` | Negative Film | RICOHの「Negative Film」ルック | ✓ | ✓ | 彩度、色相 |
| `bleach-bypass` | Bleach Bypass | RICOHの「Bleach Bypass」ルック | ✓ | ✓ | 彩度、色相 |
| `retro` | Retro | RICOHの「Retro」ルック | ✓ | ✓ | 彩度、色相 |
| `soft-monotone` | Soft Monotone | RICOHの「Soft Monotone」ルック | ✓ | | — |
| `hard-monotone` | Hard Monotone | RICOHの「Hard Monotone」ルック | ✓ | ✓ | — |
| `hi-contrast-bw` | Hi-Contrast B&W | RICOHの「Hi-Contrast B&W」ルック | ✓ | ✓ | — |
| `mono-standard` | スタンダード（2つ目） | 非表示のモノクロルック「スタンダード」 | ✓ | ✓ | — |
| `mono-soft` | Soft | 非表示のモノクロルック「Soft」 | ✓ | | — |
| `mono-solid` | Solid | 非表示のモノクロルック「Solid」 | ✓ | ✓ | — |

- 色はどのスロットでも同じです。カメラはどのスロットでもルックを同じように処理するため、フィットとそのスコアはスロットによって変わりません。
- どのスロットでも、ルックはすべてのスライダーが0、粒状感オフの状態で始まります。
- スロットによって変わるのは、どの項目を手放すかと、どのスライダーが使えるかだけです。モノクロのスロットでもルックはカラーになりますが、彩度と色相は使えません。
- **Cinema：** Color Tone設定はルックに影響しません。**Bleach Bypass：** トーン設定でルックは変わりません。**Retro：** Retro独自の調色と、周辺減光のようなトーン効果は取り除かれ、あなたのルックだけになります。
- 使わないスロットには、RICOHのルックがそのまま残ります。High Contrastにルックを入れない場合、そこはモノクロのHigh Contrastルックのままです。
- **使用できないもの：** スタンダード、Monotone、HDR Tone、Cross Processing、および非表示のGrainyとHDRのルック。これらは処理の一部をほかのルックと共有しているか、色を変えてしまう特殊な処理を使っています。
- `check`で、どのスロットに独自のルックが入っているかを一覧できます。

### 1つのファームウェアに複数のルック

各LUTを`fit`でフィットしてから、まとめてビルドします。各ルックファイルの後に、そのルック用の`--slot`（必要なら`--name`と`--icon`も）を続けます。

```sh
uv run gr4_lutsmith.py fit look_a.cube --photo R0001234.DNG -o output/a
uv run gr4_lutsmith.py fit look_b.cube --photo R0001234.DNG -o output/b
uv run gr4_lutsmith.py build output/a/look.json --slot cinema-yellow output/b/look.json --slot vivid --name "Look B" ~/Downloads/fwdc248b.bin -o output/both
```

**同時にいくつ入れられるか：** High Contrastと2つのCinemaスロットには、常にルック全体が入ります。ほかのスロットは、限られた領域を共有します。各ルックにはトーンカーブ用の領域が必要で、色相別補正やカーブ後の色補正には、さらに多くの領域が必要です。シンプルなルック（トーンカーブ1本）なら最大10スロットに同時に入りますが、色相別補正を使うルックが入る数はずっと少なくなります。入りきらない場合はツールがそう伝え、何も書き出しません。スロットを減らすか、よりシンプルなルックを使ってください。High Contrastを使わずにおくと、領域が最も多く残ります。

### スロットの名前

`--name`（`make`と`build`）を使うと、イメージコントロールのメニューとその画面で、カメラのすべての言語で、スロットに独自の名前を付けられます。

```sh
uv run gr4_lutsmith.py make my_look.cube ~/Downloads/fwdc248b.bin --slot vivid --name "Portra"
```

- スロットごとに、付けられる名前の長さに上限があります。`uv run gr4_lutsmith.py slots`で確認できます（Retroの9文字からCinema (Yellow)の23文字まで）。2つ目のモノクロのスタンダードは、カラーのスタンダードと名前を共有しているため、名前を変更できません。
- **プレーンなASCII**（英字、数字、スペース、記号）は、カメラのどの言語でも表示されます。これが安全な選択です。
- **それ以外の文字**は、その文字を使うカメラの言語で表示されます。日本語の名前はカメラを日本語に設定したときに、`Müller`はヨーロッパの言語で、`Плёнка`はロシア語で表示される、といった具合です。カメラのどの言語も使わない文字（絵文字、アラビア文字、ヘブライ文字など）は受け付けられません。
- ツールは名前を**カメラの言語**に照らして確認します。カメラの言語は、`--camera-language`を指定しない限り（たとえば`--camera-language Japanese`。`--help`で21言語すべてを確認できます）、コンピューターの言語です。その言語で使わない文字が名前に含まれている場合、ツールは表示されないおそれがあると警告し、それでもその名前を使うかを尋ねます。続けるには`y`と答えるか、`--accept-name`を付けてあらかじめ同意しておきます（スクリプトの中など、ツールが尋ねられない場合に必要です）。あとでカメラを別の言語に切り替えると、ASCII以外の名前はそこでは表示されないことがあります。
- 長い名前は、画面によっては途中で切れることがあります（中国語、日本語、韓国語の文字は、英字の約2倍の幅があります）。
- `--name`を指定しない場合、スロットは元の名前のままです。名前は`look.json`には保存されません（このファイルにはルックだけが入ります）。`build`するときに、もう一度`--name`を指定してください。`check`で、ビルド済みのファームウェアに入っている名前を確認できます。

### 独自アイコン

`--icon`（`make`と`build`）を使うと、イメージコントロールのメニューにあるスロットのアイコンを、ご自身の画像に置き換えられます。

```sh
uv run gr4_lutsmith.py make my_look.cube ~/Downloads/fwdc248b.bin --slot vivid --name "Portra" --icon portra.png
```

- どんな画像でも使えます（PNG、JPEGなど）。メニューアイコンは40×40ピクセルです。それより大きい画像や小さい画像はサイズが変更され、正方形でない場合は**中央部分**が使われます。透明な部分は透明のままなので、背景が透明なPNGはカメラ本来のアイコンのように見えます。
- `make`は結果を`icon.png`としてファームウェアと同じ場所に保存するので、カメラに表示されるとおりの見た目を確認できます。このサイズでは、シンプルで太い形が最も見やすくなります。
- 2つ目のモノクロのスタンダード以外のすべてのスロットに、独自アイコンを付けられます（このスロットはカラーのスタンダードとアイコンを共有しています）。`slots`で一覧できます。
- Pillowが必要です（`uv sync --extra photo`）。`--icon`を指定しない場合、スロットは元のアイコンのままです。アイコンは`look.json`には保存されません。`build`するときに、もう一度`--icon`を指定してください。`check`で、どのスロットに独自アイコンがあるかを確認できます。

### 共有されたルックを使う

`look.json`に入っているのは、ルックそのものだけです。つまり、色の設定と、それがLUTにどれだけフィットしているかです。スロット、名前、アイコンに関する情報や、お使いのコンピューターのフォルダは含まれません（LUTのファイル名だけは入ります）。このファイルを持っている人は、LUTもフィットもなしで、直接ファームウェアをビルドできます。スロット、名前、アイコンが同じなら、作成者と1バイトも違わない同じファームウェアになります。

アプリでは、最初のページで「共有ルック」を選びます。コマンドラインでは、ファイル名は何でもかまわないので、共有する前に好きな名前に変えてください（`portra-400.json`など）。

```sh
uv run gr4_lutsmith.py build portra-400.json ~/Downloads/fwdc248b.bin --slot vivid --name "Portra" --icon portra.png
```

- ツールはまず、ルックがLUTにどれだけフィットしているかを表示します（作成者が見た結果です。「on your photo」は作成者の写真を指します）。
- スロット、名前、アイコンは自由に選べます。[スロットの選び方](#スロットの選び方)、[スロットの名前](#スロットの名前)、[独自アイコン](#独自アイコン)を参照してください。`--slot`を指定しない場合、ルックはHigh Contrastに入ります。
- 複数のルック：各ファイルの直後に、そのファイル用の`--slot`、`--name`、`--icon`を書きます。

  ```sh
  uv run gr4_lutsmith.py build portra-400.json --slot vivid --name "Portra" tri-x.json --slot hard-monotone ~/Downloads/fwdc248b.bin -o output/both
  ```

- ファイルの内容は、ビルドの前に確認されます。壊れたファイルや、カメラが扱えない値を含むファイルは受け付けられず、何も書き出されません。
- 1.7.0より前のバージョンで作られたファイルには、スロット、名前、アイコン、LUTのフルパスが入っていることがあります。`build`はスロット、名前、アイコンを無視します（それぞれ何だったかは表示されます）。こうしたファイルを共有する前に、テキストエディタで開いて`"file"`を確認してください。

## フィットをもっと近づける

色相別補正は、毎回のフィットで試されます。もっと近づけたいときは、まず試行を増やし、次にカーブ後の色補正を試してください（[どちらが効果的か](#どちらが効果的か)を参照）。

### 色相別補正

カラーミックスとトーンカーブをフィットした後、ツールは**色相別補正**でルックの改善を試みます。カメラは、色相の12の範囲ごとに色を別々に変えられます。色相別補正は、**はっきり効果があり**（色域全体またはColorCheckerが10 %以上改善する）、**しかも何も悪化しない**（写真、グレー、ColorChecker）場合**だけ**残されます。結果の行には`hue sectors: yes`または`no`と表示されます。

- グレーが色相別補正で変わることはありません。また、隣り合う範囲は常にすき間なくつながるので、色はある色相から次の色相へなめらかに移ります。
- `--photo`を指定すると、色相別補正は実際の写真にも合わせて調整されます（推奨）。
- `--no-hue`でオフにできます（`make`と`fit`）。

### 試行を増やす

フィットはある開始点から始まり、そこから改善していきます。カメラの色の調整機能は少ないため、**フィットをどこから始めるかで、どこまで近づけるかが決まることがよくあります**。`--turns`（アプリでは「フィット」ページ）を使うと、ツールは複数のフィット（「試行」）を、それぞれ新しいランダムな開始点から実行し、良いものを残します。

```sh
uv run gr4_lutsmith.py make my_look.cube ~/Downloads/fwdc248b.bin --photo R0001234.DNG --turns 3
```

- 試行1は常に通常の開始点を使うので、試行1回（既定）では以前と同じ結果になります。2回目以降の試行は、毎回新しいランダムな開始点を選びます。
- 各試行には、通常のフィットと同じ時間（数分）がかかります。
- **同時に実行する。** `--jobs 3`を使うと、最大3つの試行を同時に実行します。各試行はプロセッサのコアを1つと、約0.8 GBのメモリを使います。コンピューターのほかの作業のために、少なくとも1コアは空けておいてください。結果は、試行を1つずつ順に実行した場合とまったく同じで、早く終わるだけです。
- **保持される結果。** 以前の結果の中に、すべての指標（色域全体、ColorChecker、グレー、写真）で同等以上のものがない限り、新しい結果は保持されます。新しい結果にすべての指標で負けた以前の結果は、一覧から外れます。そのため、保持される結果はどれも、少なくとも1つの指標でほかのすべてより優れています。ツールはそれらを並べて表示し、総合スコア（フィットに使うすべてのデータでの平均差）が最も良いものを推奨します。
- **最後に試行を追加する。** 結果が出ると、ツールは`More turns?`と尋ねます。数字を入力すると、実行を始めたときと同じ方法で、その回数だけ試行を追加します（`2`）。[カーブ後の色補正](#カーブ後の色補正)ありの試行には`a`を（`2a`）、なしの試行には`b`を（`2b`）付けます。これは、実行をどちらの方法で始めたかに関係なく使えます。新しい試行は、保持されているすべての結果と比較されます。今の結果のままでよければ、Enterを押します。
- **試行を繰り返す。** 各試行のシードは表示され、`turns.json`に保存されます。`--seed 1234`で同じ試行をもう一度実行できます（`--turns 3`と一緒なら、シードは1234、1235、1236）。

保持された結果が複数ある場合、出力フォルダは次のようになります。

```
output/my_look/look.json, fwdc248b.bin      the recommended result
output/my_look/turns/turn-1/                 every kept result, each with its
output/my_look/turns/turn-3-after-curves/    own look.json (and, with make, fwdc248b.bin)
output/my_look/turns.json                    every turn, its seed and its scores
```

保持されたほかの結果を使うには、代わりにその`fwdc248b.bin`をSDカードにコピーします。

### カーブ後の色補正

`--after-curves`（`make`と`fit`）を使うと、ツールは、カメラがトーンカーブの**後**に適用する2つ目のカラーミックスも試します。多くのフィルムルックは、シャドウとハイライトで色の変え方が異なります。通常のカラーミックスはカーブの前に働くので、それに追従できませんが、カーブの後のミックスなら追従できることがよくあります。

LUTの色域全体と実際の写真とで、結果が一致するとは限りません。あるバージョンが、彩度の高い色ではずっと近く、日常的な写真ではわずかに遠い、ということがあります。そのため、両方のバージョンが、[試行を増やす](#試行を増やす)で説明した保持される結果の一覧に入ります。カーブ後の色補正ありのバージョンは、どれか1つ（色域全体、ColorChecker、グレー、写真）で優れていれば、通常のバージョンと並んで保持され、どちらを使うかはあなたが選びます。選ぶ前に、両方をご自身の写真でプレビューしてください。

**任意である理由。** 通常のフィットの試行を増やすほうが、効果は大きくなります（[どちらが効果的か](#どちらが効果的か)を参照）。カーブ後のミックスは平均すると効果がありますが、試行ごとに数分ずつ時間が長くなります。

- グレーはグレーのままです。このミックスがニュートラルグレーに色かぶりを加えることはありません。
- フィットに数分長くかかります（追加のフィットが4回）。

- **8個は、変化したすべての指標で改善**：LUTとの平均差は3.7から2.4に下がりました（ColorChecker 1.9 → 1.1、写真 0.91 → 0.75）。

### どちらが効果的か

同じフィット時間でのテストでは、通常のフィットを4回試行し、最も良いものを続けたほうが、[カーブ後の色補正](#カーブ後の色補正)ありのフィットに、すべての段階で勝りました。それぞれランダムな試行を10回ずつ行った比較では、カーブ後の色補正ありのバージョンのほうが平均で優れていました。つまり、どちらも効果はありますが、**通常のフィットの試行を増やすほうが効果は大きくなります**。時間があれば、まず試行を増やし、そのバージョンも比べたいときに`--after-curves`を加えてください。

### 評価が不十分なLUTの場合

多くのフィルムシミュレーションLUTは、非常に鮮やかな色を、カメラの調整機能では追従できない形に変えます。そのため、日常的な写真は正しく見えても、色域全体では「不十分」になります。次の場合は、それでもファームウェアが書き出されます。

- **ColorChecker**の色の差が平均2未満、**グレー**の差が2未満で、どのグレーにも目に見える色かぶりがない。さらに`--photo`を指定した場合は、写真でもルックが不十分でない。または
- `--photo`を指定した場合に、ルックが**写真で良好**（かつ写真での差を少なくとも半分にする）で、グレーと色かぶりについても同じ条件を満たしている。

どの条件が適用されたかは、ツールが表示します。それ以外の場合は、ファームウェアを書き出しません。`--force`を付けると、それでもビルドできます。その場合は先にプレビューを確認してください。

## 知っておきたいこと

- **スライダー**（Key、Contrast、Highlight、Shadow、Sharpness、Shading、Clarity、Toning、Grain）は、ルックの上に重ねて働きます。0ならLUTどおりになります。High Contrastでは彩度と色相は使えませんが、Cinemaスロットでは使えます（[スロットの選び方](#スロットの選び方)を参照）。
- **「スタンダード」と「HDR Tone」が2つずつ。** モノクロのスタンダードとHDRのルックは、カラーのものと同じ名前とアイコンを使います。
- **RICOHの公式アップデートで、ルックは消えます。** ファームウェア全体が置き換わるためです。
- **標準のGR IV専用です。** ほかの機種には絶対にインストールしないでください。
- **カメラを修理に出す前に**、公式ファームウェアに戻してください。
- **まずはいろいろなLUTを試す：** `uv run gr4_lutsmith.py fit my_look.cube --photo R0001234.DNG`なら、ファームウェアファイルなしでフィットと結果表示ができます。

### ファームウェアファイルを確認

ファームウェアファイルをカードにコピーする前に確認してください（アプリでは、左側の**ファームウェアファイルを確認**）。

```sh
uv run gr4_lutsmith.py check path/to/fwdc248b.bin
```

ファイルが公式の1.11か、GR4-LUTSmithのファームウェアか、それ以外かがわかります。GR4-LUTSmithのファームウェアの場合は、どのスロットにルックが入っているか、その名前とアイコン、ルックが色相別補正やカーブ後のカラーミックスを使っているかも一覧表示されます。

お手持ちの公式ファイルで、ツール自体を確認するには：

```sh
uv run gr4_lutsmith.py selftest ~/Downloads/fwdc248b.bin
```

同梱の例（`examples/film-1d.cube`）をビルドし、その結果をテスト済みのビルドと比較します。`selftest: PASSED`と表示されます。

## リスク

- カメラは、正常なファームウェアファイルと壊れたファイルを見分けられません。カードにコピーするのは、このツールが書き出した（または`check`で確認した）ファイルだけにしてください。
- アップデートが中断された場合や、ファームウェアファイルが起動できない場合、カメラがアップデート機能に再びたどり着けなくなり、RICOHの修理が必要になる可能性があります。テストではこのようなことは起きていませんが、可能性は否定できません。
- カメラ固有のキャリブレーションデータには手を加えません。

## 開発者向け

```
GR4-LUTSmith/
├── README.md            this guide
├── gr4_lutsmith.py      the tool (the command line, and the engine the app uses)
├── lutsmith_app/        the app: window, translations (assets/i18n), icons and fonts
├── packaging/           building the app (packaging/build.py), its icons and licence texts
├── tests/test_app.py    checks run before every app build
├── tools/               translation check, app icon
├── pyproject.toml       dependencies (for uv)
├── uv.lock
└── examples/
    ├── film-1d.cube      a 1D film-style LUT (used by selftest)
    └── film-1d.look.json its fitted look
```

- ソースからアプリを実行する：`uv sync --extra app`の後、`uv run python -m lutsmith_app`。
- ビルドする：`uv run python packaging/build.py`（Appleシリコン搭載のMacでIntel版をビルドするには、`--arch x86_64`を追加します）。zipは`dist/`に作られます。
