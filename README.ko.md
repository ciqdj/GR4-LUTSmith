GR4-LUTSmith는 컬러 그레이딩 LUT(`.cube`)를 받아, 그 룩을 **화상 컨트롤** 룩으로
담은 GR IV 펌웨어를 만듭니다. 이 룩으로 사진, 동영상 모드, 뷰파인더에서 촬영할 수
있고, **RAW Development**에서도 사용할 수 있습니다. 카메라의 나머지는 모두 그대로
유지되며, 언제든지 공식 펌웨어로 되돌릴 수 있습니다.

이 저장소에는 RICOH 펌웨어가 들어 있지 않습니다. 공식 펌웨어는 직접 RICOH에서
다운로드하고, 함께 제공되는 도구가 본인의 컴퓨터에서 그 파일을 룩이 들어간 버전으로
바꿉니다.

> [!WARNING]
> **비공식이며, 사용에 따른 책임은 본인에게 있습니다.** RICOH IMAGING이 만들거나 보증한 것이 아닙니다.
> 수정된 펌웨어를 설치하면 보증을 받지 못할 수 있습니다. 먼저
> [시작하기 전에](#시작하기-전에)와 [위험](#위험)을 읽어 주세요.

## 작동 방식

GR IV는 LUT를 직접 실행하지 않습니다. 카메라의 룩은 몇 가지 기본 조절 기능으로
만들어집니다. 색 혼합, 톤 커브, 콘트라스트 설정, 그리고 **색상별 보정**(12개 색상
범위마다 따로 적용하는 색 변화)입니다. GR4-LUTSmith는 LUT를 이 조절 기능에 맞게
**피팅**하고, 카메라가 얼마나 가깝게 재현할 수 있는지 측정한 다음에야 펌웨어를 씁니다.

- **톤과 전체 색감에 관한 룩**은 아주 잘 맞습니다. 필름 스타일 커브, 콘트라스트,
  바랜 검정, 따뜻하거나 차가운 색조, 전체 채도 변화가 여기에 해당합니다.
- **개별 색상을 따로 움직이는 룩**(틸 오렌지, 녹색이나 하늘을 바꾸는 필름
  시뮬레이션, …)은 **색상별 보정**으로 피팅합니다. 색 혼합만 쓸 때보다 훨씬
  가까워집니다. 색의 채도에 크게 좌우되는 변화(예: 가장 선명한 빨강에만 적용되는
  변화)는 근사치로 남으며, 그런 경우에는 도구가 알려 줍니다.
- **로그 및 카메라 전용 변환 LUT**(S-Log, V-Log, …)는 지원하지 않습니다. 일반
  (Rec.709 / sRGB) 사진용으로 만든 “크리에이티브” LUT를 사용하세요.

피팅 결과는 두 색이 얼마나 다르게 보이는지를 나타내는 표준 척도인 **CIEDE2000**으로
판정합니다. 기준으로 삼자면 **1 미만은 나란히 놓고 봐도 구별하기 어렵고**, 2 정도는
조금 보이는 차이입니다.

| 결과 | 의미 |
| --- | --- |
| **좋음** | 평균 차이가 1 미만이고 색의 95 %가 2 미만: 똑같아 보임 |
| **근사** | 평균 2 미만: 가깝지만 일부 색에서 차이가 보임 |
| **미흡** | 카메라가 LUT의 전체 색 범위를 재현할 수 없음. **일상적인 색**이 맞으면 펌웨어는 그래도 만들어짐([LUT가 “미흡”일 때](#lut가-미흡일-때) 참조) |

모든 LUT는 세 가지 방식으로 측정합니다. LUT의 전체 색 범위, **ColorChecker** 차트의
일상적인 24색(피부, 하늘, 나뭇잎, …), 그리고 **뉴트럴 그레이**(색 캐스트가 가장 잘
보이는 곳)입니다. 직접 찍은 사진을 지정하면(`--photo`) 그 사진에서도 측정합니다.

## 설치 결과

설치하면 화상 컨트롤 목록의 끝부분이 다음과 같이 됩니다. 화상 컨트롤, 표준, 채도, 색상을 제외한 메뉴
이름은 카메라를 영어로 설정했을 때의 표시대로 적었습니다.

| 표시 이름 | 룩 | 사진 | 동영상 |
| --- | --- | :---: | :---: |
| HDR Tone | (기존 컬러 룩) | ✓ | |
| 표준 | 흑백 표준 | ✓ | ✓ |
| Solid | 흑백 Solid | ✓ | ✓ |
| Soft | 흑백 Soft | ✓ | |
| **High Contrast** | **LUT의 룩(컬러)** | ✓ | ✓ |
| Grainy | 흑백 Grainy | ✓ | |
| HDR Tone | 흑백 HDR *(실험적)* | ✓ | |

- 룩은 **High Contrast**의 이름과 아이콘을 사용합니다(첫 번째 “HDR Tone” 다음 네 번째
  항목). 대신 **Cinema (Yellow)**, **Vivid** 또는 다른 슬롯을 고르거나 여러 슬롯을
  함께 쓸 수도 있습니다. [슬롯 선택](#슬롯-선택)을 참조하세요.
  [자체 이름](#슬롯-이름-정하기)과 [자체 아이콘](#자체-아이콘)을 표시할 수도 있습니다.
- 룩은 **모든 슬라이더가 0**, 샤프니스는 표준값, **그레인은 꺼진** 상태로 시작합니다.
  LUT의 룩은 이 설정을 기준으로 들어가 있으며, 슬라이더는 룩을 출발점으로 하여 평소처럼
  작동합니다.
- GR IV Monochrome의 흑백 룩 다섯 가지도 GR4-MonoUnlock과 마찬가지로 사용할 수
  있습니다.
- 기존 룩은 모두 그대로입니다.

## 시작하기 전에

- **카메라:** RICOH GR IV(표준 컬러 모델). 다른 모델은 지원하지 않습니다.
- **카메라가 이미 펌웨어 1.11이어야 합니다.** 카메라의 설정 메뉴에서 버전을
  확인하세요.
  - 이전 버전: 먼저 RICOH 공식 파일로 일반적인 방법에 따라 1.11로 업데이트하세요.
  - 더 새로운 버전: **이 도구를 사용하지 마세요.** 1.11만 지원합니다.
- **공식 펌웨어 파일.** RICOH IMAGING의 공식 GR IV 지원 페이지에서 **펌웨어 버전 1.11**을
  다운로드하세요. 필요하면 압축을 풀어 **`fwdc248b.bin`** 파일을 얻으세요.
- **완전히 충전된 배터리.** 펌웨어 업데이트 중에는 절대 전원이 끊기면 안 됩니다.
- 포맷해도 되는 **SD 카드**.
- `.cube` 파일(3D 또는 1D)로 된 **LUT**, 그리고 그 LUT가 **sRGB**(대부분의 LUT)용인지
  **Adobe RGB**용인지에 대한 정보.
- **권장:** GR IV로 찍은 DNG 사진. 도구는 이 사진으로 실제 장면에서 룩을 확인하고
  미리 보기를 만듭니다.
- 다시 설정하고 싶지 않은 사용자 설정(C1, C2, …)은 적어 두세요.

그런 다음 [앱](#앱) 또는 [명령줄](#명령줄)로 펌웨어를 만드세요.

## 앱

### 다운로드

[최신 릴리스](../../releases/latest)에서 컴퓨터에 맞는 파일을 다운로드하세요.

| 컴퓨터 | 파일 |
| --- | --- |
| Apple 실리콘(M1 이상) Mac | `GR4-LUTSmith-<version>-macOS-AppleSilicon.zip` |
| Intel 프로세서 Mac | `GR4-LUTSmith-<version>-macOS-Intel.zip` |
| Windows 10 또는 11(64비트) | `GR4-LUTSmith-<version>-Windows-x64.zip` |

macOS 12(Monterey) 이상이 필요합니다. 어떤 Mac인지 모르겠다면 Apple 메뉴 →
**이 Mac에 관하여**를 여세요. “칩 Apple M…”이면 Apple 실리콘, “프로세서 Intel”이면
Intel입니다.

각 zip에는 앱과 `Licences` 폴더(앱을 이루는 구성 요소들의 라이선스)가 들어 있습니다.

<summary><strong>이 프로젝트에서 만든 파일인지 확인하기</strong>(선택 사항)</summary>

<br>

모든 zip은 GitHub에서 이 저장소 자체의 빌드로 만들어지며, 이 빌드는 파일의 출처 기록에
서명합니다. 출처 기록에는 저장소, 빌드, 코드의 정확한 버전이 들어 있습니다.
[GitHub CLI](https://cli.github.com)(`gh auth login`으로 로그인한 상태)로, 다운로드한
파일이 바로 그 파일이며 변경되거나 바꿔치기되지 않았는지 확인할 수 있습니다.

```sh
gh attestation verify GR4-LUTSmith-2.1.0-macOS-AppleSilicon.zip --repo lemonadesaltbagel/GR4-LUTSmith
```

(다운로드한 zip의 이름을 사용하세요. Windows에서는 다운로드 폴더에서 PowerShell로
실행하세요.) 결과는 “Verification succeeded!”로 끝나고, 파일을 만든 빌드가 표시됩니다.
다른 결과가 나오면 파일을 열지 말고 릴리스 페이지에서 다시 다운로드하세요. 저장소의
**Attestations** 페이지에 서명된 모든 파일이 나와 있습니다.

다운로드가 완전한지 더 빠르게 확인하는 방법도 있습니다. 릴리스의 `SHA256SUMS`에 모든
파일의 SHA-256이 나와 있습니다.

- macOS(터미널): `shasum -a 256 ~/Downloads/GR4-LUTSmith-*.zip`
- Windows(PowerShell): `Get-FileHash $HOME\Downloads\GR4-LUTSmith-*.zip -Algorithm SHA256`

이 방법은 파일이 손상 없이 도착했다는 것만 보여 줄 뿐, 누가 만들었는지는 보여 주지
않습니다. `SHA256SUMS`가 zip과 같은 페이지에 있기 때문입니다.

다운로드를 아예 건너뛸 수도 있습니다. 소스 코드에서 앱을 실행하거나
([개발자용](#개발자용) 참조), [명령줄](#명령줄)로 펌웨어를 만드세요. 앱과 명령줄은
정확히 같은 `fwdc248b.bin`을 만들며, `uv run gr4_lutsmith.py check fwdc248b.bin`으로
어떤 펌웨어 파일이든 그 내용을 확인할 수 있습니다.

### 처음 열기

앱은 무료이며 유료 Apple 또는 Microsoft 인증서로 서명되어 있지 않습니다. 그래서
컴퓨터가 이 앱을 신뢰하는지 한 번 묻습니다.

**macOS**

1. 파일의 압축을 풀고 **GR4-LUTSmith**를 응용 프로그램 폴더로 옮기세요.
2. 앱을 여세요. macOS가 앱에 악성 소프트웨어가 있는지 확인할 수 없다고 알립니다.
   **완료**(macOS 15) 또는 **취소**를 선택하세요.
3. **시스템 설정 → 개인정보 보호 및 보안**을 열고, 아래로 스크롤하여 GR4-LUTSmith에 관한
   메시지에서 **그래도 열기**를 선택한 다음, 암호를 입력해 확인하세요.
   macOS 12~14에서는 대신 앱을 Control-클릭하고 **열기**를 선택한 다음, 다시 **열기**를
   선택해도 됩니다.

그다음부터는 평소처럼 열립니다.

**Windows**

1. zip 파일을 마우스 오른쪽 버튼으로 클릭 → **Extract All…**(압축 풀기)을 선택하고,
   압축을 푼 **GR4-LUTSmith** 폴더를 여세요(zip 안에서 바로 실행하지 마세요).
2. **GR4-LUTSmith.exe**를 여세요. “Windows의 PC 보호”가 표시되면
   **추가 정보 → 실행**을 선택하세요.

폴더 전체를 함께 두세요. 앱 옆에 `_internal` 폴더가 있어야 합니다.

### 사용하기

앱이 화면에서 단계를 하나씩 안내합니다. 카메라의 펌웨어 파일, LUT(선택적으로 DNG),
슬롯과 그 이름 및 아이콘, 피팅, 빌드 순서입니다. 앱은 `fwdc248b.bin`을 원하는 위치에
저장합니다. 그런 다음 [카메라에 설치하세요](#카메라에-설치하기).

- **언어:** 앱은 컴퓨터의 언어를 따릅니다. 창 위쪽에서 바꿀 수 있습니다. 이 언어는 슬롯
  이름을 검사하는 기준이 되는 카메라 언어이기도 합니다([슬롯 이름 정하기](#슬롯-이름-정하기) 참조).
- **화면 모드:** 창 위쪽에서 시스템, 주간, 야간 중에서 고릅니다.
- **펌웨어 파일 확인**(왼쪽)은 `fwdc248b.bin`이 RICOH의 공식 파일인지, GR4-LUTSmith로
  만든 것인지(어떤 룩이 들어 있는지), 아니면 다른 것인지 알려 줍니다.
- 다른 사람이 공유한 룩(`.json`)도 앱에서 사용할 수 있습니다. 첫 페이지에서 “공유 룩”을
  선택하세요.
- **여러 시도를 동시에:** 피팅 페이지에서 시도 횟수와 동시에 실행할 개수를 고르세요(시도마다
  프로세서 코어 하나 사용, [시도 횟수 늘리기](#시도-횟수-늘리기) 참조). 각 시도의 진행
  상황이 표시됩니다. 실행 중에도 시도를 추가할 수 있으며, “모두 중지”를 눌러도 완료된
  시도는 보관됩니다. 시도가 끝나는 대로 결과가 표에 추가됩니다.

### 문제가 생겼을 때

- **macOS에서 앱이 손상되었다고 표시될 때**: 다시 다운로드하고(파일이 중간에 끊긴
  것입니다), [이 프로젝트에서 만든 파일인지 확인하기](#다운로드)의 방법으로 확인하세요.
- **Windows에서 앱이 시작되지 않을 때**: zip 전체의 압축을 풀었는지 확인하고, 압축을 푼
  폴더에서 `GR4-LUTSmith.exe`를 실행하세요.
- **펌웨어 파일이 거부될 때**: 앱은 수정되지 않은 RICOH GR IV 1.11 `fwdc248b.bin`만
  받아들입니다. 이미 GR4-LUTSmith로 변경한 파일은 다시 변경할 수 없습니다. 수정되지 않은
  파일에서 시작하세요.

### 2. 펌웨어 만들기

경로는 본인의 것으로 바꾸세요.

```sh
uv run gr4_lutsmith.py make my_look.cube ~/Downloads/fwdc248b.bin --photo R0001234.DNG
```

| 옵션 | 기능 |
| --- | --- |
| `--space adobe` | LUT가 Adobe RGB용으로 만들어졌을 때 |
| `--photo R0001234.DNG` | 사진에서도 룩을 확인합니다(선택 사항이지만 권장) |
| `--slot vivid`, `--slot cinema-yellow`, … | High Contrast 대신 다른 룩의 자리에 룩을 넣습니다: [슬롯 선택](#슬롯-선택) |
| `--name "My Look"` | 슬롯을 자체 이름으로 표시합니다: [슬롯 이름 정하기](#슬롯-이름-정하기) |
| `--icon my_icon.png` | 슬롯에 자체 메뉴 아이콘을 지정합니다: [자체 아이콘](#자체-아이콘) |
| `--turns 3` | 피팅을 세 번 실행하고 좋은 결과들을 보관합니다: [시도 횟수 늘리기](#시도-횟수-늘리기) |
| `--jobs 3` | 그 시도들을 최대 세 개까지 동시에 실행합니다: [시도 횟수 늘리기](#시도-횟수-늘리기) |
| `--after-curves` | 두 번째 색 혼합도 시도합니다: [커브 이후 색 보정](#커브-이후-색-보정) |

도구는 다음을 수행합니다.

1. 제공한 파일이 진짜 공식 1.11 파일인지 확인합니다.
2. LUT를 피팅하고(몇 분 걸리며, 색상별 보정에 1~2분이 더 걸립니다) 얼마나 잘 맞는지
   보여 줍니다.
3. 펌웨어를 빌드하고 검사합니다.

정상적으로 실행되면 다음과 같이 끝납니다.

```
  result: GOOD  (ΔE00 0.6, p95 1.42; without the look 2.09)
  on your photo: ΔE00 1.22 (without the look 2.55)
  ...
wrote output/my_look/fwdc248b.bin  (SHA-256 …)
Copy this file to the root of the SD card and run the camera's firmware update.
Then choose High Contrast in Image Control: your look is there.
```

도구는 시작할 때 룩이 어느 슬롯에 들어가는지도 알려 줍니다. 예:
`slot: High Contrast (replaces the hidden monochrome High Contrast look)`.

출력 폴더 `output/my_look/`에는 `look.json`(피팅된 룩)도 들어 있으며, 미리 보기
(3단계)도 이 폴더에 만들 수 있습니다. `look.json`은 다른 GR IV 사용자와 공유할 수
있습니다. 받은 사람은 다시 피팅하지 않고 같은 룩을 빌드합니다
([공유받은 룩 사용하기](#공유받은-룩-사용하기) 참조).

LUT를 잘 재현할 수 없거나 펌웨어 파일이 공식 1.11이 아니면, 도구는 `refused: …`를
출력하고 **펌웨어를 쓰지 않습니다**.

### 3. 미리 보기(선택 사항)

```sh
uv run gr4_lutsmith.py preview output/my_look/look.json R0001234.DNG
```

이 명령은 세 패널로 된 `output/my_look/preview.jpg`를 씁니다. 룩 적용 전의 카메라,
LUT 자체, 그리고 룩을 **적용한** 카메라입니다. LUT 패널에는 `.cube` 파일이 필요합니다.
도구가 `look.json` 옆이나 현재 폴더에서 찾으며, `--lut my_look.cube`로 지정할 수도
있습니다. 파일이 없으면 미리 보기에는 나머지 두 패널만 표시됩니다. 비교할 것은 색과
톤입니다. 샤프닝과 노이즈는 시뮬레이션하지 않습니다.

그런 다음 [카메라에 설치하세요](#카메라에-설치하기).

## 카메라에 설치하기

앱에서 만든 펌웨어와 명령줄로 만든 펌웨어 모두 방법이 같습니다.

### 1. SD 카드에 복사하기

1. **카메라에서 SD 카드를 포맷하세요.**
2. **`fwdc248b.bin`**(명령줄의 경우 `output/my_look/fwdc248b.bin`)을 카드의
   **최상위 위치**에 복사하세요. 폴더 안에 넣지 말고, 이름은 정확히
   `fwdc248b.bin` 그대로 두세요.

### 2. 카메라 업데이트하기

1. 완전히 충전된 배터리와 SD 카드를 넣으세요.
2. RICOH 공식 GR IV 펌웨어 업데이트 안내에 따라 카메라의 설정 메뉴에서 펌웨어
   업데이트를 시작하세요.
3. **카메라에 버전 1.11에서 버전 1.11로 업데이트한다고 표시됩니다.** 이는 정상입니다.
   수정된 펌웨어는 버전 번호를 그대로 유지합니다. 업데이트를 확인하세요.

> [!CAUTION]
> **업데이트가 끝나고 카메라가 다시 시작될 때까지 카메라 전원을 끄거나, 배터리
> 덮개나 카드 덮개를 열거나, 카드를 빼지 마세요.**

### 3. 촬영하기

- **화상 컨트롤**을 열고 **High Contrast**(첫 번째 “HDR Tone” 다음)를 선택하세요. 이제
  컬러입니다. 다른 슬롯을 골랐다면 그 항목을 선택하세요.
- 펌웨어 버전은 여전히 **1.11**로 표시됩니다. 정상입니다.
- 업데이트가 실수로 다시 시작되지 않도록 카드에서 `fwdc248b.bin`을 삭제하세요(또는
  카드를 포맷하세요).

나중에 다른 LUT로 바꾸려면 **공식** 파일에서 새 펌웨어를 만들어 같은 방법으로
설치하세요.

### 공식 펌웨어로 되돌리기

1~2단계를 RICOH의 **공식** `fwdc248b.bin`으로 다시 하세요. 카메라에 다시
**1.11 → 1.11**이 표시됩니다. 확인하면 카메라가 원래 상태로 돌아갑니다.

## 나만의 설정

룩이 들어갈 위치, 그 이름, 메뉴에서의 모양을 정합니다. 앱에서는 슬롯 단계에 있고,
명령줄에서는 `make`와 `build`의 옵션입니다.

### 슬롯 선택

룩은 카메라의 룩 하나를 대체합니다. 어느 룩을 대체할지는 `--slot`(`make` 및 `build`)으로
고릅니다. `uv run gr4_lutsmith.py slots`를 실행하면 터미널에 같은 목록이 표시됩니다.

| `--slot` | 표시 이름 | 대체 대상 | 사진 | 동영상 | 추가 슬라이더 |
| --- | --- | --- | :---: | :---: | --- |
| `high-contrast` (기본값) | High Contrast | 숨겨진 흑백 룩 ‘High Contrast’ | ✓ | ✓ | — |
| `cinema-yellow` | Cinema (Yellow) | RICOH의 ‘Cinema (Yellow)’ 룩 | ✓ | ✓ | 채도, 색상 |
| `cinema-green` | Cinema (Green) | RICOH의 ‘Cinema (Green)’ 룩 | ✓ | ✓ | 채도, 색상 |
| `vivid` | Vivid | RICOH의 ‘Vivid’ 룩 | ✓ | ✓ | 채도, 색상 |
| `positive-film` | Positive Film | RICOH의 ‘Positive Film’ 룩 | ✓ | ✓ | 채도, 색상 |
| `negative-film` | Negative Film | RICOH의 ‘Negative Film’ 룩 | ✓ | ✓ | 채도, 색상 |
| `bleach-bypass` | Bleach Bypass | RICOH의 ‘Bleach Bypass’ 룩 | ✓ | ✓ | 채도, 색상 |
| `retro` | Retro | RICOH의 ‘Retro’ 룩 | ✓ | ✓ | 채도, 색상 |
| `soft-monotone` | Soft Monotone | RICOH의 ‘Soft Monotone’ 룩 | ✓ | | — |
| `hard-monotone` | Hard Monotone | RICOH의 ‘Hard Monotone’ 룩 | ✓ | ✓ | — |
| `hi-contrast-bw` | Hi-Contrast B&W | RICOH의 ‘Hi-Contrast B&W’ 룩 | ✓ | ✓ | — |
| `mono-standard` | 표준(두 번째) | 숨겨진 흑백 룩 ‘표준’ | ✓ | ✓ | — |
| `mono-soft` | Soft | 숨겨진 흑백 룩 ‘Soft’ | ✓ | | — |
| `mono-solid` | Solid | 숨겨진 흑백 룩 ‘Solid’ | ✓ | ✓ | — |

- 색은 모든 슬롯에서 같습니다. 카메라는 어느 슬롯에서든 룩을 같은 방식으로 처리하므로,
  피팅과 그 점수는 슬롯에 따라 바뀌지 않습니다.
- 룩은 어느 슬롯에서든 모든 슬라이더가 0이고 그레인이 꺼진 상태로 시작합니다.
- 슬롯에 따라 달라지는 것은 어떤 항목을 잃고 어떤 슬라이더를 얻는지뿐입니다. 흑백
  슬롯에서도 룩은 컬러입니다. 다만 그 슬롯에서는 채도와 색상이 제공되지 않습니다.
- **Cinema:** Color Tone 설정은 룩에 영향을 주지 않습니다.
  **Bleach Bypass:** 톤 설정은 룩을 바꾸지 않습니다.
  **Retro:** Retro 자체의 토닝과 비네팅 같은 톤 효과가 제거되므로, 룩만 그대로
  적용됩니다.
- 사용하지 않는 슬롯은 RICOH의 룩을 유지합니다. High Contrast에 룩을 넣지 않으면 흑백
  High Contrast 룩으로 남습니다.
- **사용할 수 없음:** 표준, Monotone, HDR Tone, Cross Processing, 그리고 숨겨진 Grainy 및
  HDR 룩. 이 룩들은 처리 과정의 일부를 다른 룩과 공유하거나, 색을 바꿔 버리는 특수
  처리를 사용합니다.
- `check`는 어느 슬롯에 자체 룩이 들어 있는지 보여 줍니다.

### 하나의 펌웨어에 여러 룩

각 LUT를 `fit`으로 피팅한 다음 함께 빌드하세요. 각 룩 파일 바로 뒤에 그 룩의
`--slot`을(원하면 `--name`, `--icon`도) 적습니다.

```sh
uv run gr4_lutsmith.py fit look_a.cube --photo R0001234.DNG -o output/a
uv run gr4_lutsmith.py fit look_b.cube --photo R0001234.DNG -o output/b
uv run gr4_lutsmith.py build output/a/look.json --slot cinema-yellow output/b/look.json --slot vivid --name "Look B" ~/Downloads/fwdc248b.bin -o output/both
```

**한 번에 몇 개까지:** High Contrast와 두 Cinema 슬롯은 항상 룩 전체를 담습니다.
나머지 슬롯은 한정된 공간을 함께 씁니다. 각 룩은 톤 커브를 위한 공간이 필요하고,
색상별 보정과 커브 이후 색 보정에는 훨씬 더 많은 공간이 필요합니다. 단순한 룩(톤 커브
1개)은 최대 10개 슬롯에 동시에 넣을 수 있지만, 색상별 보정이 있는 룩은 훨씬 적게
들어갑니다. 공간이 부족하면 도구가 알려 주고 아무것도 쓰지 않습니다. 슬롯 수를 줄이거나
더 단순한 룩을 사용하세요. 공간을 가장 많이 확보하려면 High Contrast를 비워 두세요.

### 슬롯 이름 정하기

`--name`(`make` 및 `build`)은 화상 컨트롤 메뉴와 관련 화면에서, 카메라의 모든 언어로
슬롯에 자체 이름을 붙입니다.

```sh
uv run gr4_lutsmith.py make my_look.cube ~/Downloads/fwdc248b.bin --slot vivid --name "Portra"
```

- 슬롯마다 받을 수 있는 이름 길이가 정해져 있습니다. `uv run gr4_lutsmith.py slots`로
  확인할 수 있습니다(Retro의 9자부터 Cinema (Yellow)의 23자까지). 두 번째 흑백 표준은
  컬러 표준 룩과 이름을 함께 쓰기 때문에 이름을 바꿀 수 없습니다.
- **일반 ASCII**(영문자, 숫자, 공백, 문장 부호)는 모든 카메라 언어에서 표시됩니다.
  가장 안전한 선택입니다.
- **그 밖의 글자와 문자**는 그 문자를 쓰는 카메라 언어에서 표시됩니다. 일본어 이름은
  카메라를 일본어로 설정했을 때, `Müller`는 유럽 언어에서, `Плёнка`는 러시아어에서
  표시되는 식입니다. 카메라의 어떤 언어에서도 쓰지 않는 문자(이모지, 아랍 문자, 히브리
  문자, …)는 거부됩니다.
- 도구는 이름을 **카메라 언어** 기준으로 검사합니다. 카메라 언어는 `--camera-language`를
  지정하지 않으면 컴퓨터의 언어입니다(예: `--camera-language Japanese`, 21개 언어 전체는
  `--help`에 나옵니다). 이름에 그 언어가 쓰지 않는 문자가 있으면, 도구는 표시되지 않을
  수 있다고 경고하고 그래도 그 이름을 쓸지 묻습니다. 계속하려면 `y`를 입력하세요. 미리
  동의하려면 `--accept-name`을 추가하세요(스크립트 안처럼 도구가 물어볼 수 없을 때
  필요합니다). 나중에 카메라를 다른 언어로 바꾸면 ASCII가 아닌 이름은 그 언어에서
  표시되지 않을 수 있습니다.
- 긴 이름은 일부 화면에서 잘릴 수 있습니다(중국어, 일본어, 한국어 문자는 영문자의 약 두
  배 너비를 차지합니다).
- `--name`을 지정하지 않으면 슬롯은 원래 이름을 유지합니다. 이름은 `look.json`에 저장되지
  않습니다(이 파일에는 룩만 들어 있습니다). `build`할 때 `--name`을 다시 지정하세요.
  `check`는 빌드된 펌웨어의 이름을 보여 줍니다.

### 자체 아이콘

`--icon`(`make` 및 `build`)은 화상 컨트롤 메뉴의 슬롯 아이콘을 직접 고른 이미지로
바꿉니다.

```sh
uv run gr4_lutsmith.py make my_look.cube ~/Downloads/fwdc248b.bin --slot vivid --name "Portra" --icon portra.png
```

- 어떤 이미지든 사용할 수 있습니다(PNG, JPEG, …). 메뉴 아이콘은 40×40픽셀입니다. 이보다
  크거나 작은 이미지는 크기가 조정되고, 정사각형이 아니면 **가운데** 부분이 사용됩니다.
  투명한 부분은 투명하게 유지되므로, 배경이 투명한 PNG는 카메라 자체 아이콘처럼
  보입니다.
- `make`는 결과를 펌웨어 옆에 `icon.png`로 저장하므로, 카메라에 표시될 모습을 정확히 볼
  수 있습니다. 이 크기에서는 단순하고 굵은 모양이 가장 잘 보입니다.
- 두 번째 흑백 표준을 제외한 모든 슬롯에 자체 아이콘을 넣을 수 있습니다(그 슬롯은 컬러
  표준 룩과 아이콘을 함께 씁니다). `slots`에 목록이 나옵니다.
- Pillow가 필요합니다(`uv sync --extra photo`). `--icon`을 지정하지 않으면 슬롯은 원래
  아이콘을 유지합니다. 아이콘은 `look.json`에 저장되지 않습니다. `build`할 때 `--icon`을
  다시 지정하세요. `check`는 어느 슬롯에 자체 아이콘이 있는지 보여 줍니다.

### 공유받은 룩 사용하기

`look.json`에는 룩 자체, 즉 색 설정과 그 설정이 LUT에 얼마나 잘 맞는지만 들어 있습니다.
슬롯, 이름, 아이콘에 관한 정보는 없으며, 컴퓨터의 폴더 정보도 없습니다(LUT의 파일
이름만 있습니다). 이 파일이 있으면 누구든 LUT도 피팅도 없이 바로 펌웨어를 빌드할 수
있으며, 같은 슬롯, 이름, 아이콘이라면 제작자와 바이트 단위까지 똑같은 펌웨어를 얻습니다.

앱에서는 첫 페이지에서 “공유 룩”을 선택하세요. 명령줄에서는 파일 이름이 무엇이든
상관없으므로, 공유하기 전에 원하는 대로 이름을 바꾸세요(`portra-400.json`, …).

```sh
uv run gr4_lutsmith.py build portra-400.json ~/Downloads/fwdc248b.bin --slot vivid --name "Portra" --icon portra.png
```

- 도구는 먼저 룩이 원본 LUT에 얼마나 잘 맞는지 보여 줍니다(제작자가 본 결과이며,
  “on your photo”는 제작자의 사진을 뜻합니다).
- 슬롯, 이름, 아이콘은 [슬롯 선택](#슬롯-선택), [슬롯 이름 정하기](#슬롯-이름-정하기),
  [자체 아이콘](#자체-아이콘)에서처럼 직접 고릅니다. `--slot`을 지정하지 않으면 룩은
  High Contrast에 들어갑니다.
- 여러 룩: 각 파일 바로 뒤에 그 파일의 `--slot`, `--name`, `--icon`을 적으세요.

  ```sh
  uv run gr4_lutsmith.py build portra-400.json --slot vivid --name "Portra" tri-x.json --slot hard-monotone ~/Downloads/fwdc248b.bin -o output/both
  ```

- 빌드하기 전에 파일 내용을 먼저 검사합니다. 손상된 파일이나 카메라가 받아들일 수 없는
  값이 있는 파일은 거부되며, 아무것도 쓰지 않습니다.
- 1.7.0 이전 버전으로 만든 파일에는 슬롯, 이름, 아이콘, LUT의 전체 경로가 들어 있을
  수도 있습니다. `build`는 슬롯, 이름, 아이콘을 무시합니다(무엇이었는지는 알려 줍니다).
  이런 파일은 공유하기 전에 텍스트 편집기로 열어 `"file"`을 확인하세요.

## 더 가깝게 피팅하기

색상별 보정은 피팅할 때마다 시도합니다. 더 가깝게 맞추고 싶다면 먼저 시도 횟수를
늘리고, 그다음 커브 이후 색 보정을 시도하세요([어느 쪽이 더 도움이 되나](#어느-쪽이-더-도움이-되나) 참조).

### 색상별 보정

색 혼합과 톤 커브를 피팅한 뒤, 도구는 **색상별 보정**으로 룩을 더 개선하려고 합니다.
카메라는 12개 색상 범위에서 색을 따로 바꿀 수 있습니다. 색상별 보정은 **분명히 도움이
될 때만**(전체 색 범위 또는 ColorChecker가 10 % 이상 개선) **그리고 아무것도 나빠지지
않을 때만**(사진, 회색, ColorChecker) 유지됩니다. 결과 줄에 `hue sectors: yes` 또는
`no`가 표시됩니다.

- 회색은 색상별 보정으로 절대 바뀌지 않으며, 이웃한 범위는 항상 빈틈없이 이어지므로 색이
  한 색상에서 다음 색상으로 매끄럽게 넘어갑니다.
- `--photo`를 사용하면 색상별 보정이 실제 사진에도 맞게 조정됩니다(권장).
- `--no-hue`로 끌 수 있습니다(`make` 및 `fit`).

### 시도 횟수 늘리기

피팅은 하나의 시작점에서 출발해 그곳부터 개선해 나갑니다. 카메라의 색 조절 기능은 몇
가지뿐이므로, **피팅이 어디서 시작하느냐가 얼마나 가까워질지를 좌우하는 경우가 많습니다**.
`--turns`를 사용하면(앱에서는 피팅 페이지에서) 도구가 피팅을 여러 번(“시도”) 실행합니다.
시도마다 새로운 무작위 시작점에서 출발하며, 좋은 결과를 보관합니다.

```sh
uv run gr4_lutsmith.py make my_look.cube ~/Downloads/fwdc248b.bin --photo R0001234.DNG --turns 3
```

- 시도 1은 항상 기본 시작점을 사용하므로, 1회 시도(기본값)는 이전과 같은 결과를 냅니다.
  그 뒤의 시도는 모두 새로운 무작위 시작점을 뽑습니다.
- 각 시도는 일반 피팅만큼(몇 분) 걸립니다.
- **나란히 실행.** `--jobs 3`은 최대 세 개의 시도를 동시에 실행하며, 시도마다 프로세서
  코어 하나와 약 0.8 GB의 메모리를 사용합니다. 컴퓨터의 나머지 작업을 위해 코어를 최소
  하나는 남겨 두세요. 결과는 시도를 차례로 실행했을 때와 정확히 같으며, 더 빨리 나올
  뿐입니다.
- **보관된 결과.** 새 결과는, 이전 결과 중 하나가 모든 지표(전체 범위, ColorChecker,
  회색, 사진)에서 같거나 더 좋지 않은 한 보관됩니다. 새 결과가 모든 지표에서 앞서는 이전
  결과는 목록에서 빠집니다. 따라서 보관된 결과는 모두 적어도 한 가지 지표에서 다른 모든
  결과보다 낫습니다. 도구는 이 결과들을 나란히 보여 주고, 종합 점수(피팅에 쓰는 모든
  것에 대한 평균 차이)가 가장 좋은 결과를 권장합니다.
- **끝에 시도 추가.** 결과가 나오면 도구가 `More turns?`라고 묻습니다. 숫자를 입력하면
  실행이 시작된 것과 같은 방식으로 그만큼 더 실행합니다(`2`). 실행이 어느 방식으로
  시작되었든, [커브 이후 색 보정](#커브-이후-색-보정)을 포함한 시도는 `a`를 붙이고
  (`2a`), 포함하지 않은 시도는 `b`를 붙이세요(`2b`). 새 시도는 보관된 모든 결과와
  비교됩니다. 지금 결과를 그대로 두려면 Enter를 누르세요.
- **시도 반복.** 모든 시도의 시드는 화면에 표시되고 `turns.json`에 저장됩니다.
  `--seed 1234`는 같은 시도를 다시 실행합니다(`--turns 3`과 함께 쓰면 시드 1234, 1235,
  1236).

보관된 결과가 둘 이상이면 출력 폴더는 다음과 같습니다.

```
output/my_look/look.json, fwdc248b.bin      the recommended result
output/my_look/turns/turn-1/                 every kept result, each with its
output/my_look/turns/turn-3-after-curves/    own look.json (and, with make, fwdc248b.bin)
output/my_look/turns.json                    every turn, its seed and its scores
```

보관된 다른 결과를 쓰려면, 그 결과의 `fwdc248b.bin`을 대신 SD 카드에 복사하세요.

### 커브 이후 색 보정

`--after-curves`(`make` 및 `fit`)를 사용하면, 도구는 카메라가 톤 커브 **이후에** 적용하는
두 번째 색 혼합도 시도합니다. 많은 필름 룩은 섀도와 하이라이트에서 색을 다르게
바꿉니다. 일반 색 혼합은 커브 이전에 작용하므로 이를 따라갈 수 없지만, 커브 이후의
혼합은 따라갈 수 있는 경우가 많습니다.

LUT의 전체 색 범위와 실제 사진의 결과가 항상 일치하지는 않습니다. 어떤 버전은 채도 높은
색에서는 훨씬 가깝지만 일상적인 사진에서는 조금 멀 수 있습니다. 그래서 두 버전 모두
[시도 횟수 늘리기](#시도-횟수-늘리기)에서 설명한 보관 결과 목록에 들어갑니다. 커브 이후
색 보정 버전은 어느 한 가지(전체 범위, ColorChecker, 회색, 사진)에서라도 더 좋으면 일반
버전과 함께 보관되며, 선택은 사용자가 합니다. 고르기 전에 직접 찍은 사진으로 두 버전을
미리 보세요.

**선택 사항인 이유.** 일반 피팅의 시도 횟수를 늘리는 쪽이 더 큰 효과가 있습니다
([어느 쪽이 더 도움이 되나](#어느-쪽이-더-도움이-되나) 참조). 커브 이후의 혼합은
평균적으로 도움이 되지만, 시도마다 몇 분씩 더 걸립니다.

- 회색은 회색으로 유지됩니다. 이 혼합은 뉴트럴 그레이에 색 캐스트를 절대 더하지 않습니다.
- 피팅이 몇 분 더 걸립니다(추가 피팅 4회).

### 어느 쪽이 더 도움이 되나

같은 피팅 시간으로 한 테스트에서, 일반 피팅 4회 시도 중 가장 좋은 결과를 이어서 진행한
쪽이 [커브 이후 색 보정](#커브-이후-색-보정)을 사용한 피팅을 모든 단계에서 앞섰습니다.
각각 무작위 시도 10회씩을 비교하면, 커브 이후 색 보정 버전이 평균적으로 더 좋았습니다.
따라서 둘 다 도움이 되지만, **일반 피팅의 시도 횟수를 늘리는 쪽이 더 큰 효과를 냅니다**.
시간이 있다면 먼저 시도 횟수를 늘리고, 그 버전도 비교하고 싶을 때 `--after-curves`를
추가하세요.

### LUT가 “미흡”일 때

많은 필름 시뮬레이션 LUT는 채도가 매우 높은 색을 카메라의 조절 기능이 따라갈 수 없는
방식으로 바꿉니다. 그래서 일상적인 사진은 제대로 보이는데도 전체 색 범위에서는
“미흡”이 됩니다. 다음 경우에는 펌웨어를 그래도 씁니다.

- **ColorChecker** 색의 평균 차이가 2 미만, **회색**의 차이가 2 미만이고, 어떤 회색에도
  눈에 보이는 색 캐스트가 없을 때. 그리고 `--photo`를 사용했다면 사진에서 룩이 미흡하지
  않을 때. 또는
- `--photo`를 사용했고 룩이 **사진에서 좋음**이며(그리고 사진에서의 차이를 적어도 절반으로
  줄이며), 회색과 색 캐스트의 한도가 같을 때.

도구는 어느 규칙이 적용되었는지 알려 줍니다. 그렇지 않으면 펌웨어를 쓰지 않습니다.
그래도 빌드하려면 `--force`를 추가하고, 먼저 미리 보기를 확인하세요.

## 알아 두면 좋은 점

- **슬라이더**(Key, Contrast, Highlight, Shadow, Sharpness, Shading, Clarity, Toning,
  Grain)는 룩 위에 작용합니다. 0이면 LUT 그대로입니다. 채도와 색상은 High Contrast에서는
  제공되지 않지만 Cinema 슬롯에서는 제공됩니다([슬롯 선택](#슬롯-선택) 참조).
- **“표준”과 “HDR Tone” 항목이 각각 두 개.** 흑백 표준과 HDR 룩은 컬러 룩과 같은 이름과
  아이콘을 사용합니다.
- **RICOH 공식 업데이트를 설치하면 룩이 사라집니다.** 펌웨어 전체를 교체하기 때문입니다.
- **표준 GR IV 전용입니다.** 다른 모델에는 절대 이 파일을 설치하지 마세요.
- **카메라를 수리에 보내기 전에** 공식 펌웨어로 되돌리세요.
- **먼저 여러 LUT를 시험해 보세요:** `uv run gr4_lutsmith.py fit my_look.cube --photo R0001234.DNG`는
  펌웨어 파일 없이 피팅하고 결과를 보고합니다.

### 펌웨어 파일 확인

펌웨어 파일을 카드에 복사하기 전에 확인하세요(앱에서는 왼쪽의 **펌웨어 파일 확인**).

```sh
uv run gr4_lutsmith.py check path/to/fwdc248b.bin
```

이 명령은 파일이 공식 1.11인지, GR4-LUTSmith 펌웨어인지, 아니면 다른 것인지 알려 줍니다.
GR4-LUTSmith 펌웨어라면 어느 슬롯에 룩이 들어 있는지, 그 이름과 아이콘, 그리고 룩이
색상별 보정과 커브 이후 색 혼합을 사용하는지도 보여 줍니다.

공식 파일로 도구 자체를 검사하려면 다음을 실행하세요.

```sh
uv run gr4_lutsmith.py selftest ~/Downloads/fwdc248b.bin
```

이 명령은 함께 제공되는 예제(`examples/film-1d.cube`)를 빌드하고, 그 결과를 테스트된
빌드와 비교합니다. `selftest: PASSED`가 출력됩니다.

## 위험

- 카메라는 정상적인 펌웨어 파일과 손상된 파일을 구별하지 못합니다. 도구가 쓴(또는
  `check`로 확인한) 파일만 카드에 복사하세요.
- 업데이트가 중단되거나 펌웨어 파일이 시작되지 못하면, 카메라가 다시 업데이트 기능에
  들어가지 못할 수 있으며, 그러면 RICOH 서비스가 필요합니다. 테스트 중에는 이런 일이
  없었지만, 가능성을 배제할 수는 없습니다.
- 카메라 고유의 캘리브레이션 데이터는 건드리지 않습니다.

| 슬라이더가 0으로 시작(그레인 꺼짐) | 테스트된 빌드와 같은 변경(그 일부)으로 구성됨. 이것만 단독으로는 아직 설치해 보지 않음 |
| 톤 커브가 2개 또는 3개 필요한 룩(색 캐스트, 토닝 룩) | 커브 3개를 GR IV 1.11에서 테스트함 |
| 색상별 보정 | GR IV 1.11의 RAW Development에서 필름 시뮬레이션 LUT로 테스트함(ISO 200, 녹색과 노랑이 많은 주광 장면): 카메라가 도구의 예측과 일치했고, 색이 있는 부분에서 LUT와의 차이가 약 30 % 줄었으며, 색 사이의 틈은 보이지 않았음. 빨강, 파랑, 보라와 더 높은 ISO는 아직 카메라에서 확인하지 않음 |
| 커브 이후 색 보정(`--after-curves`, 선택 사항) | 
| Cinema (Yellow) / Cinema (Green) 슬롯의 룩 | GR IV 1.11에서 테스트함: 작동함 |
| 다른 슬롯의 룩(Vivid, Positive Film, Negative Film, Bleach Bypass, Retro, 흑백 슬롯) | GR IV 1.11에서 테스트함: 작동함 |
| 슬롯의 자체 이름(`--name`) | GR IV 1.11에서 테스트함: 작동함 |
| 슬롯의 자체 아이콘(`--icon`) | GR IV 1.11에서 테스트함: 작동함 |
| 공유받은 `look.json`으로 빌드 | 오프라인으로 확인함: 같은 LUT 결과, 슬롯, 이름, 아이콘으로 `make`한 것과 펌웨어가 바이트 단위로 동일함. 카메라에 새로 들어가는 것은 없음 |
| 앱(`GR4-LUTSmith`)이 명령줄과 같은 펌웨어를 빌드함 | 오프라인으로 확인함: 같은 LUT, 사진, 선택이면 바이트 단위로 동일함 |
| 시도 동시 실행(`--jobs`, 앱의 “동시 실행”) | 오프라인으로 확인함: 같은 시도를 차례로 실행한 것과 결과가 바이트 단위로 동일함 |
| 도구가 테스트된 예제를 정확히 재현함 | 테스트함(`selftest`) |

## 개발자용

```
GR4-LUTSmith/
├── README.md            this guide
├── gr4_lutsmith.py      the tool (the command line, and the engine the app uses)
├── lutsmith_app/        the app: window, translations (assets/i18n), icons and fonts
├── packaging/           building the app (packaging/build.py), its icons and licence texts
├── tests/test_app.py    checks run before every app build
├── tools/               translation check, app icon
├── pyproject.toml       dependencies (for uv)
├── uv.lock
└── examples/
    ├── film-1d.cube      a 1D film-style LUT (used by selftest)
    └── film-1d.look.json its fitted look
```

- 소스에서 앱 실행: `uv sync --extra app` 다음 `uv run python -m lutsmith_app`.
- 빌드: `uv run python packaging/build.py`(Apple 실리콘 Mac에서 Intel 빌드를 만들려면
  `--arch x86_64` 추가). zip은 `dist/`에 생성됩니다.
